# AGENTS.md

Flask website for Enactus ADGIPS (live at enactus-adgips.vercel.app). The actual app lives in `enactus/`; the repo root only holds git config, `.gitignore`, and stray files (`ENACTUS HOMEPAGE.docx`, `r.txt` — a duplicate of `enactus/requirements.txt`).

## Commands
- Run locally: from `enactus/`, `python app.py` — starts on port 5005 with `debug=True` and runs `seed_database()` on startup.
- Deploy: `vercel` (set `DATABASE_URL` env var; see `vercel.json`). No other build config.
- No tests, linter, typechecker, or CI exist. `requirements.txt` is fully pinned; `r.txt` is kept in sync by hand.

## Architecture
- `enactus/app.py` is the entire backend: two models (`Event`, `Registration`), public routes, session-based admin routes, PDF (reportlab) and Excel (openpyxl) exports, and `seed_database()`.
- `enactus/templates/*.html` — Jinja2 templates. `layout.html` is shared; every page carries large inline `<style>`/`<script>` blocks. `index.html` is tracked but unused (`home.html` is rendered for `/`).
- `enactus/static/js/script.js` holds the team roster in the `teamData` object (tenure `"10.0"`, categories `council`/`department`/`project`) and `legacyData`. Team and legacy pages are fully client-rendered — edit members in `script.js`, not `team.html`. Portrait cards support per-member `pos` (CSS `object-position`) and `scale` overrides.
- `enactus/static/js/world_map_data.js` is generated by `enactus/generate_normalized_map.py` (downloads a remote GeoJSON); commit the output, don't inline it.

## Database
- Local dev: SQLite `enactus/enactus.db`. Production (Vercel/Neon): Postgres via `DATABASE_URL` (code rewrites `postgres://` → `postgresql://`).
- Postgres needs `psycopg2-binary` (in `requirements.txt`); Neon connection strings carry `sslmode=require` and work as-is.
- `enactus/schema.sql` bootstraps a Postgres DB (Neon): DROP + CREATE `event`/`registration` + the 6 seed events (mirrors `seed_database()`). Run in the Neon SQL editor or `psql "$DATABASE_URL" -f schema.sql`. It wipes existing data — fresh setups only.
- No migration tool. `seed_database()` calls `db.create_all()` each boot and performs a one-off raw `ALTER TABLE event ADD COLUMN brochure_link` for existing DBs. If you add a column, follow that same ALTER pattern or existing databases break; the block re-runs every boot.
- Seeds 6 events only when the `event` table has ≤1 row — wiping events and restarting re-seeds. Event/registration content is edited via the admin UI, not by editing `app.py`.
- `seed_database()` is called only under `__main__`, so Vercel/Postgres deploys get tables only via that same path — the module itself never calls `db.create_all()` on import.
- Both `enactus.db` and the stale `emactus.db` (typo) are tracked in git; the `*.db` ignore rule in `.gitignore` is commented out.

## Gotchas
- Admin login password (`enactus_adgips`) and `app.secret_key` are hardcoded in `app.py`. Keep the flow working if you refactor; don't commit real secrets.
- Asset paths under `static/images/team/` contain spaces and parentheses (e.g. `static/images/team/Council/1) President.jpg`) and are referenced from JS — keep exact filenames and URL-encode where needed.
- `convert_images.py` and `update_about_script.py` hardcode paths to another machine (`C:\Users\akash\...`); they are one-off local utilities, not part of the app. Don't run them as-is.
- `store_response.html` (in `enactus/`) is a leftover standalone copy — the `/store` route renders `templates/store.html`. Don't edit it expecting changes to the store page.
- `openpyxl` is optional (guarded import); `reportlab` is required.
